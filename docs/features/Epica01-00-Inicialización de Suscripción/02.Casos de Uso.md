# Historias de Usuario

## US-01 — Crear suscripción de cliente desde Backoffice

**Tipo:** Funcional

**Prioridad:** Alta

**Actor:** Project Manager

### Descripción

El Project Manager debe poder registrar una nueva suscripción para un cliente desde el Backoffice tras el cierre de una venta. Esta suscripción será el punto de partida para la creación del entorno del cliente en la plataforma.

### Datos mínimos requeridos

- Nombre de la empresa cliente
- Tipo / plan de suscripción
- Nombre del administrador
- Apellidos del administrador
- Email del administrador

### Criterios de aceptación

- El Project Manager puede acceder a una pantalla de creación de suscripción.
- El formulario solicita los datos mínimos definidos.
- El sistema valida los datos antes de permitir continuar.
- Al confirmar, se registra una nueva suscripción en estado **Pending Initialization** (o equivalente).
- La suscripción queda registrada en Backoffice.

### Dependencias

Ninguna.

## US-02 — Crear Tenant asociado a la suscripción

**Tipo:** Sistema

**Prioridad:** Alta

**Actor:** Sistema

### Descripción

Cuando se inicializa una suscripción, el sistema debe crear automáticamente un **tenant único** que representará el espacio organizativo del cliente dentro de la plataforma.

### Criterios de aceptación

- El sistema genera un **tenantId único**.
- El tenant queda asociado a la suscripción creada.
- El tenant se registra en la base de datos de tenants.
- El sistema evita la creación duplicada de tenants para una misma suscripción.
- El tenant queda en estado **Active** tras su creación.

### Dependencias

US-01

## US-03 — Crear empresa propietaria de la suscripción

**Tipo:** Sistema

**Prioridad:** Alta

**Actor:** Sistema

### Descripción

El sistema debe crear la primera empresa dentro del tenant. Esta empresa representará al cliente comprador y será la propietaria de la suscripción.

### Criterios de aceptación

- Se crea una empresa dentro del tenant.
- La empresa queda marcada como **Owner Company**.
- La empresa queda asociada al tenant.
- La suscripción queda vinculada a esta empresa.
- La empresa tiene un **companyId único**.

### Dependencias

US-01

US-02

## US-04 — Crear usuario administrador del cliente

**Tipo:** Funcional

**Prioridad:** Alta

**Actor:** Sistema / Project Manager

### Descripción

Durante el proceso de inicialización debe crearse un usuario administrador perteneciente a la empresa principal. Este usuario tendrá el mayor nivel de permisos permitido por la suscripción.

### Criterios de aceptación

- Se crea un usuario con los datos proporcionados.
- El usuario queda asociado a la empresa propietaria.
- El usuario recibe el rol **Company Admin** (o equivalente).
- El email del usuario debe ser único dentro del tenant.
- El usuario queda en estado **Pending Activation**.

### Dependencias

US-03

## US-05 — Establecer relaciones entre entidades del cliente

**Tipo:** Sistema

**Prioridad:** Alta

**Actor:** Sistema

### Descripción

El sistema debe garantizar que las entidades creadas durante el onboarding quedan correctamente relacionadas entre sí.

### Relaciones requeridas

Suscripción → Tenant

Tenant → Empresa

Empresa → Usuario

### Criterios de aceptación

- Cada suscripción tiene exactamente **un tenant**.
- Cada tenant tiene al menos **una empresa**.
- La empresa principal queda identificada como propietaria de la suscripción.
- El usuario administrador queda asociado a la empresa principal.
- Todas las relaciones pueden consultarse desde Backoffice.

## US-06 — Ejecutar proceso completo de onboarding del cliente

**Tipo:** Funcional

**Prioridad:** Alta

**Actor:** Project Manager

### Descripción

El Project Manager debe poder ejecutar el proceso completo de inicialización del cliente desde el Backoffice mediante un flujo guiado.

Este flujo ejecutará automáticamente:

1. Creación de suscripción
2. Creación de tenant
3. Creación de empresa propietaria
4. Creación de usuario administrador
5. Vinculación de entidades

### Criterios de aceptación

- El Project Manager puede iniciar el flujo desde Backoffice.
- El flujo solicita los datos necesarios.
- El sistema ejecuta automáticamente los pasos internos.
- El proceso informa si la inicialización fue exitosa.
- Si falla algún paso, el sistema informa del error.

## US-07 — Validar datos antes de ejecutar el onboarding

**Tipo:** Funcional

**Prioridad:** Alta

**Actor:** Sistema

### Descripción

Antes de ejecutar la inicialización del cliente, el sistema debe validar que todos los datos requeridos están presentes y cumplen las reglas de negocio.

### Validaciones mínimas

Empresa

- Nombre obligatorio

Administrador

- Nombre obligatorio
- Apellidos obligatorios
- Email válido

Suscripción

- Tipo de plan obligatorio

### Criterios de aceptación

- El sistema valida los datos antes de iniciar el proceso.
- Si falta información obligatoria, se muestran errores claros.
- El usuario puede corregir los datos.
- El proceso solo puede ejecutarse con datos válidos.

### Dependencias

## US-08 — Mostrar resumen del cliente creado en Backoffice

**Tipo:** Funcional

**Prioridad:** Media

**Actor:** Project Manager

### Descripción

Tras completar el proceso de onboarding, el Backoffice debe mostrar un resumen con la información principal del cliente creado.

### Información visible

- Suscripción
- Tenant
- Empresa principal
- Usuario administrador
- Estado del onboarding

### Criterios de aceptación

- El Project Manager puede acceder al resumen del cliente.
- La información se muestra de forma estructurada.
- Las entidades pueden consultarse desde el Backoffice.
- El estado del onboarding queda registrado.

## US-09 — Preparar el tenant para futuras empresas

**Tipo:** Arquitectura

**Prioridad:** Media

**Actor:** Sistema

### Descripción

El modelo de datos debe permitir que en el futuro puedan añadirse nuevas empresas dentro del mismo tenant, soportando estructuras B2B más complejas.

### Criterios de aceptación

- Un tenant puede contener múltiples empresas.
- La empresa inicial queda marcada como **Owner Company**.
- El modelo permite añadir nuevas empresas en el futuro.
- Las nuevas empresas heredan el contexto del tenant.
