## Entregables

### 1. Aggregate Root: `CustomerActivationProcess`

Máquina de estados dual (`Status` + `Step`) que modela el ciclo de vida de activación del customer.

**Status (flujo general):**

```
Draft → InProgress → WaitingForNotificationDelivery → WaitingForUserActivation → InProgress → Completed
                                                                                              ↘ Failed (recuperable vía Retry)
```

**Step (milestone de progreso):**

```
None → ActivationRequested → ActivationDelivered → UserActivated → CustomerReady → Completed
```

**Métodos del agregado:**

| Método | Transición Status | Transición Step | Domain Event |
|--------|-------------------|-----------------|--------------|
| `Create()` | → Draft | → None | `CustomerActivationProcessStartedDomainEvent` |
| `Start()` | Draft → InProgress | — | — |
| `RequestActivation()` | InProgress → WaitingForNotificationDelivery | None → ActivationRequested | `ActivationEmailRequestedDomainEvent` |
| `MarkActivationDelivered()` | WaitingForNotificationDelivery → WaitingForUserActivation | ActivationRequested → ActivationDelivered | — |
| `MarkUserActivated(userId)` | WaitingForUserActivation → InProgress | ActivationDelivered → UserActivated | `CustomerAdminActivatedDomainEvent` |
| `MarkCustomerReady()` | — | UserActivated → CustomerReady | — |
| `Complete()` | InProgress → Completed | CustomerReady → Completed | `CustomerGoLiveDomainEvent` |
| `Fail(code, message)` | * → Failed | — | — |
| `Retry()` | Failed → InProgress | (preserva step actual) | — |

**Guards implementados:**
- Validación de IDs requeridos en `Create()` (SubscriptionId, TenantId, OwnerCompanyId, AdminUserId, AdminMembershipId).
- Verificación estricta de estado y paso previo en cada transición.
- `MarkUserActivated()` valida que el `userId` coincida con `AdminUserId`.
- `Fail()` no permitido desde `Completed`.
- `Retry()` solo desde `Failed`, incrementa `RetryCount`, limpia errores, preserva `CurrentStep`.

## Decisiones de Diseño

1. **Separación del agregado OnboardingProcess:** `CustomerActivationProcess` es un agregado independiente, no una extensión de `OnboardingProcess`. Esto permite evolución independiente y evita acoplar los ciclos de vida.

2. **Máquina de estados dual:** `Status` controla el estado general del proceso (incluye estados de espera); `Step` rastrea el progreso granular del milestone. Esto permite que `Retry()` preserve el step actual mientras resetea el status.

3. **V1 Simplification:** La transición `MarkCustomerReady()` se ejecutará automáticamente después de `MarkUserActivated()` (decisión de diseño V1 documentada en el plan). No requiere readiness checks adicionales en MVP.

4. **Índice único en SubscriptionId:** Garantiza que solo puede existir un proceso de activación por suscripción, previene duplicados a nivel de base de datos.
