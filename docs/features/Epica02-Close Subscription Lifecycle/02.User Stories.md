# 02.User Stories

# 🟩 US-01 — Start Customer Activation Process

## Title

**Start Customer Activation Process after onboarding completion**

---

## Description

As a **Project Manager / System**,

I want the system to automatically start a **Customer Activation Process**

when onboarding (Epic 1) is completed,

so that the customer can activate their admin user and access the platform.

---

## Acceptance Criteria

```
Given an onboarding process is completed
When the system triggers activation
Then a CustomerActivationProcess is created

And its status is "InProgress"
And its currentStep is "ActivationRequested"

And an ActivationEmailRequestedIntegrationEvent is published
```

---

## Tasks

- [ ]  Account: Create `CustomerActivationProcess` aggregate
- [ ]  Account: Implement `Create + Start + RequestActivation`
- [ ]  Account: Publish `ActivationEmailRequestedIntegrationEvent`
- [ ]  Account: Hook from onboarding completion handler
- [ ]  Tests: happy path + duplicate protection

---

## Notes

- Trigger = `ExternalUserProvisionedIntegrationEventHandler` (post-completion)
- Idempotency required

---

# 🟩 US-02 — Send Activation Email

## Title

**Send activation email to customer admin user**

---

## Description

As a **Notifications Service**,

I want to send an activation email to the customer admin user,

so that they can activate their account.

---

## Acceptance Criteria

```
Given an ActivationEmailRequestedIntegrationEvent is received
When the Notifications service processes it
Then an activation email is sent to the user

And an ActivationDeliveredIntegrationEvent is published
```

---

## Tasks

- [ ]  Notifications: Create handler
- [ ]  Notifications: Generate activation link (Identity)
- [ ]  Notifications: Send email
- [ ]  Notifications: Publish `ActivationDeliveredIntegrationEvent`
- [ ]  Tests: delivery success + retry

---

## Notes

- Email template required
- Language support (`preferredLanguage`)

---

# 🟩 US-03 — Mark Activation Delivered

## Title

**Update activation process when email is delivered**

---

## Description

As the **Account Service**,

I want to update the activation process when the activation email is delivered,

so that the system reflects the correct state.

---

## Acceptance Criteria

```
Given an ActivationDeliveredIntegrationEvent is received
When the activation process is in "WaitingForNotificationDelivery"
Then the process transitions to "WaitingForUserActivation"

And currentStep becomes "ActivationDelivered"
```

---

## Tasks

- [ ]  Account: Integration event handler
- [ ]  Account: Implement `MarkActivationDelivered`
- [ ]  Tests: valid transition + invalid state rejection

---

# 🟩 US-04 — Handle User Activation (Identity → Account)

## Title

**Handle user activation event from Identity**

---

## Description

As the **Account Service**,

I want to react to user activation from Identity,

so that the customer activation process can progress.

---

## Acceptance Criteria

```
Given a UserActivatedIntegrationEvent is received
When it matches the admin user of the process
Then the activation process moves to "UserActivated"

And status becomes "InProgress"
```

---

## Tasks

- [ ]  Identity: Publish `UserActivatedIntegrationEvent`
- [ ]  Account: Handle event
- [ ]  Account: Implement `MarkUserActivated`
- [ ]  Tests: valid user + invalid user

---

## Notes

- Correlation via `UserId + TenantId`

---

# 🟩 US-05 — Complete Customer Activation (Go-Live)

## Title

**Complete activation process and mark customer as live**

---

## Description

As the **Account Service**,

I want to complete the activation process once the user is activated and the tenant is ready,

so that the customer becomes operational.

---

## Acceptance Criteria

```
Given the activation process is in "UserActivated"
When readiness conditions are met
Then the process is marked as "Completed"

And a CustomerGoLiveIntegrationEvent is published
```

---

## Tasks

- [ ]  Account: Implement `MarkCustomerReady`
- [ ]  Account: Implement `Complete`
- [ ]  Account: Publish `CustomerGoLiveIntegrationEvent`
- [ ]  Tests: full happy path

---

## Notes

- V1: readiness puede ser automático (sin configuración extra)

# 🟩 US-06 — Retry Activation Process

## Title

**Allow retry of failed activation process**

---

## Description

As a **Project Manager**,

I want to retry a failed activation process,

so that I can recover from errors (email failure, etc.).

---

## Acceptance Criteria

```
Given an activation process is in "Failed"
When a retry is triggered
Then the process transitions to "InProgress"

And retryCount is incremented
And lastError is cleared
```

---

## Tasks

- [ ]  Account: Implement `Retry()`
- [ ]  Account: API endpoint `/activation-processes/{id}/retry`
- [ ]  Tests: retry + guards

---

# 🟩 US-10 — Authorization (Backoffice)

## Title

**Secure activation process operations with role-based access**

---

## Description

As a **Platform**,

I want activation operations to be secured,

so that only authorized internal users can perform them.

---

## Acceptance Criteria

```
Given a user without proper role
When accessing activation endpoints
Then access is denied (403)

Given a ProjectManager
Then access is allowed
```

---
