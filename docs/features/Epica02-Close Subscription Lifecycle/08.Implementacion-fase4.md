## Objetivo

Conectar el servicio de Notifications con el ciclo de activación (Epic 2). Cuando `Accounts` emite `ActivationEmailRequestedIntegrationEvent`, el servicio `Notifications` recibe el evento, envía el email de activación al admin y publica `ActivationDeliveredIntegrationEvent` al outbox para que `Accounts` pueda avanzar el `CustomerActivationProcess` al siguiente paso.

### 3. `EmailService.SendActivationEmailAsync` — implementación simulada

Sigue el mismo patrón de simulación que los métodos existentes: crea un `EmailNotification` con `EmailType.ActivationEmail`, lo agrega a `_sentEmails` y registra con el emoji `📧`:

```csharp
public Task SendActivationEmailAsync(string toEmail, string? companyName, Guid activationProcessId)
{
    var email = new EmailNotification
    {
        Id = Guid.NewGuid(),
        To = toEmail,
        Subject = $"Your account is now active{(companyName is not null ? $" - {companyName}" : string.Empty)}",
        Body = $"Your account has been activated successfully. Activation reference: {activationProcessId}",
        Type = EmailType.ActivationEmail,
        Status = NotificationStatus.Sent,
        CreatedAt = DateTime.UtcNow,
        SentAt = DateTime.UtcNow
    };

    _sentEmails.Add(email);

    _logger.LogInformation(
        "📧 SIMULATED - Activation email sent to {Email} for company {CompanyName}, ActivationProcessId={ActivationProcessId}",
        toEmail, companyName, activationProcessId);

    return Task.CompletedTask;
}
```

### 4. `ActivationEmailRequestedIntegrationEventHandler` — handler principal

El handler implementa `IIntegrationEventHandler<ActivationEmailRequestedIntegrationEvent>` e inyecta `ILogger`, `IEmailService` e `IEventBusOutboxService`.

**Flujo del `Handle`:**

```
1. Log informational (ActivationProcessId + Email)
2. await _emailService.SendActivationEmailAsync(AdminEmail, CompanyLegalName, ActivationProcessId)
3. await _outboxService.AddAndSaveEventAsync(new ActivationDeliveredIntegrationEvent(...))
4. Log informational (confirmación de entrega + publicación)
```

El paso 3 solo se alcanza si el paso 2 no lanza excepción. Si el envío de email falla, el evento de outbox **no se publica**, preservando la consistencia: `ActivationDeliveredIntegrationEvent` solo se emite cuando el email fue efectivamente procesado.

**Construcción del evento de outbox:**

```
@event.ActivationProcessId → ActivationProcessId
@event.AdminUserId         → UserId
@event.AdminEmail          → Email
DateTimeOffset.UtcNow      → DeliveredAtUtc
@event.CorrelationId       → CorrelationId
```

## Decisiones de Diseño

1. **Email primero, outbox segundo — sin transacción compartida:** El email simulado y el `AddAndSaveEventAsync` son operaciones independientes. En producción, si el email se envía pero el outbox falla, el sistema quedará en estado inconsistente. Para la implementación simulada actual esto es aceptable; cuando se integre un proveedor real (SendGrid, Azure Communication Services), se evaluará si el email debe persistirse junto al outbox en la misma transacción o si se acepta la eventual consistencia con reintento vía idempotency key en el handler.

2. **`CompanyLegalName` nullable en `SendActivationEmailAsync`:** El campo es `string?` en `ActivationEmailRequestedIntegrationEvent` (snapshot opcional del onboarding). La firma del método refleja esa nulabilidad en lugar de forzar un string vacío, preservando la información semántica para el template del email.

3. **`ActivationDeliveredIntegrationEvent` publicado al outbox, no directamente al bus:** Consistent con la arquitectura del servicio — todos los eventos salientes pasan por el outbox para garantizar entrega at-least-once y correlación con la transacción de base de datos.

4. **`Notifications.Contracts.AssemblyReference` registrado en el outbox:** El `OutboxProcessor` usa reflexión sobre los assemblies registrados para deserializar eventos pendientes. Sin este registro, los mensajes de `ActivationDeliveredIntegrationEvent` quedarían atascados en la tabla de outbox con error de deserialización.

5. **Test de timestamp con `Callback<IntegrationEvent>` (base type):** `IEventBusOutboxService.AddAndSaveEventAsync` recibe `IntegrationEvent` (tipo base). Moq requiere que el tipo del `Callback` coincida con el parámetro del método — se usa el tipo base y se castea internamente en el test.
