# 1. 🎯 Responsabilidad del agregado

## `CustomerActivationProcess`

Aggregate encargado de:

> Orquestar la activación real del cliente desde que el admin es provisionado hasta que el cliente está operativo (Go-Live)
> 

---

## 🔒 Invariantes clave

- No puede activarse sin `AdminUserId`
- No puede completarse sin `AdminMembershipId`
- No puede estar en `Completed` sin `UserActivated`
- No puede avanzar pasos fuera de orden (state machine estricta)
- Retry solo permitido desde `Failed`

# 4. 🔁 Transiciones (API del agregado)

## 🟩 Creación

```
publicstaticCustomerActivationProcessCreate(
GuidsubscriptionId,
GuidtenantId,
GuidownerCompanyId,
GuidadminUserId,
GuidadminMembershipId)
{
if (subscriptionId==Guid.Empty)throw ...
if (tenantId==Guid.Empty)throw ...
if (adminUserId==Guid.Empty)throw ...

varprocess=newCustomerActivationProcess
    {
SubscriptionId=subscriptionId,
TenantId=tenantId,
OwnerCompanyId=ownerCompanyId,
AdminUserId=adminUserId,
AdminMembershipId=adminMembershipId,
Status=ActivationStatus.Draft,
CurrentStep=ActivationStep.None,
StartedAtUtc=DateTimeOffset.UtcNow
    };

process.AddDomainEvent(newCustomerActivationProcessStartedDomainEvent(process.Id));

returnprocess;
}
```

## ▶️ Start

```
publicvoidStart()
{
EnsureStatus(ActivationStatus.Draft);

}
```

## 📩 Request Activation

```
publicvoidRequestActivation()
{
EnsureStatus(ActivationStatus.InProgress);
EnsureStep(ActivationStep.None);

CurrentStep=ActivationStep.ActivationRequested;
Status=ActivationStatus.WaitingForNotificationDelivery;

ActivationRequestedAtUtc=DateTimeOffset.UtcNow;

Id,

}
```

---

## 📬 Mark Activation Delivered

```
publicvoidMarkActivationDelivered()
{
EnsureStatus(ActivationStatus.WaitingForNotificationDelivery);
EnsureStep(ActivationStep.ActivationRequested);

CurrentStep=ActivationStep.ActivationDelivered;
Status=ActivationStatus.WaitingForUserActivation;

ActivationDeliveredAtUtc=DateTimeOffset.UtcNow;
}
```

---

## 👤 Mark User Activated (evento desde Identity)

```
publicvoidMarkUserActivated(GuiduserId)
{
EnsureStatus(ActivationStatus.WaitingForUserActivation);
EnsureStep(ActivationStep.ActivationDelivered);

if (userId!=AdminUserId)
thrownewDomainException("Invalid user");

CurrentStep=ActivationStep.UserActivated;
Status=ActivationStatus.InProgress;

UserActivatedAtUtc=DateTimeOffset.UtcNow;

AddDomainEvent(newCustomerAdminActivatedDomainEvent(Id,userId));
}
```

---

## 🧪 Mark Customer Ready

```
publicvoidMarkCustomerReady()
{
EnsureStatus(ActivationStatus.InProgress);
EnsureStep(ActivationStep.UserActivated);

CurrentStep=ActivationStep.CustomerReady;
}
```

---

## ✅ Complete (Go-Live)

```
publicvoidComplete()
{
EnsureStatus(ActivationStatus.InProgress);
EnsureStep(ActivationStep.CustomerReady);

Status=ActivationStatus.Completed;
CurrentStep=ActivationStep.Completed;
CompletedAtUtc=DateTimeOffset.UtcNow;

AddDomainEvent(newCustomerGoLiveDomainEvent(
SubscriptionId,
TenantId,
AdminUserId));
}
```

---

## ❌ Fail

```
publicvoidFail(stringcode,stringmessage)
{
if (Status==ActivationStatus.Completed)
throw ...

Status=ActivationStatus.Failed;
LastErrorCode=code;
LastErrorMessage=message;
}
```

---

## 🔁 Retry

```
publicvoidRetry()
{
EnsureStatus(ActivationStatus.Failed);

RetryCount++;
LastErrorCode=null;
LastErrorMessage=null;

Status=ActivationStatus.InProgress;

// NO reset de step → recovery desde punto exacto
}
```

# 8. 🧠 Decisiones clave de diseño

---

## ✔ Separación de procesos

- Epic 1 → provisioning
- Epic 2 → activation

👉 evita “God aggregate”

---

## ✔ Step NO se resetea en Retry

Permite recovery granular (igual que onboarding)

---

## ✔ Eventos como frontera entre servicios

- Identity nunca llama Account directamente
- Notifications nunca conoce Account internamente

---

## ✔ Complete = Go-Live (no shortcut)

A diferencia de Epic 1:

👉 aquí `Complete()` **sí es semánticamente correcto**
