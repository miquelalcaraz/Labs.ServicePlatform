# Resumen Ejecutivo — Implementación Épica 01: Inicialización de Suscripción

## 1. Objetivo

Implementar el flujo completo de inicialización de un nuevo cliente B2B en la plataforma QLT System. Desde que un Project Manager registra una suscripción en el Backoffice, el sistema crea automáticamente la estructura base (Subscription, Tenant, Company, Usuario Administrador) mediante comunicación event-driven entre los servicios Account e Identity.

Esta épica es la **primera feature construida sobre la arquitectura base** de la plataforma, validando los patrones de CQRS, Domain Events, Transactional Outbox, Idempotent Consumer y consistencia eventual entre microservicios.

## 4. Decisiones de arquitectura relevantes

### Split-context en Identity
Identity opera con dos DbContexts separados:
- **IdentityContext** — ASP.NET Identity + Duende IdentityServer (gestión de usuarios, tokens, clients)
- **IdentityLogsContext** — QltDBContext de la plataforma (idempotencia, outbox, proyecciones)

Implicación: la creación del usuario y la publicación del evento outbox no comparten transacción. Se mitiga con diseño retry-safe (`GetByEmailAsync` antes de crear).

### OnboardingProcess como máquina de estados
Se modeló el onboarding con pasos explícitos (`OnboardingStep` enum) y transiciones validadas. En v1 se implementaron los pasos 1-5 y Complete, omitiendo los pasos 6-7 (notificación de activación vía Notifications service).

### RegisterEventTypes — Patrón single-call
Se descubrió que `OutboxMessageOptions.RegisterEventTypes(IEnumerable<Type>)` **reemplaza** la lista de tipos en cada invocación (no es aditivo). Al registrar eventos de múltiples assemblies, se debe usar el overload `params Assembly[]` en una única llamada.

### Namespace global:: qualifier
El proyecto `Identity.Contracts` comparte prefijo de namespace con `Identity`, lo que genera ambigüedad. Se resolvió usando el calificador `global::` para referenciar `Identity.Contracts.AssemblyReference`.
